## 2024-05-13 - [Scroll Progress Reactivity]
**Learning:** `src/components/blog/ReadingProgress.tsx` uses `useState` inside a `scroll` event listener to update a reading progress bar. This triggers a React re-render on *every* scroll event, causing layout thrashing and high CPU usage. The project memory states: "When implementing scroll-bound animations (like progress bars) in React components, avoid updating component state within a `scroll` event listener, as it triggers constant React re-renders and potential layout thrashing. Instead, use `framer-motion`'s `useScroll` hook combined with a CSS transform and origin class (e.g., `<m.div className="origin-left" style={{ scaleX: scrollYProgress }} />`) to bypass the React render cycle and delegate animations directly to the compositor."
**Action:** Use framer-motion's `useScroll` and `m.div` to delegate the scroll animation to the compositor.
